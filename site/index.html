Netflix doesn't show you IMDb ratings. So choosing means opening a second tab for every title that looks vaguely interesting — search, squint at the number, close the tab, go back, and by the fourth one you've stopped choosing and started scrolling. Four hundred cards, all equally bright, none of them telling you anything.

How it works

Three steps, and only one of them touches the network.

  1. 01

    Import the ratings once

    IMDb publishes every rated title as a bulk dataset — 1.7 million rows, about 8 MB gzipped, regenerated daily. On first run the extension imports it onto your own machine, which takes roughly a minute, and refreshes it once on each day you use it. After that, looking up a rating is a local read.

  2. 02

    Match the name to the title

    Netflix only gives a display name, and that name frequently isn't IMDb's. One small lookup resolves it to an IMDb id, then caches the answer permanently — each title costs one lookup once, ever. Because the ratings index is already local, the extension can check whether a candidate is actually rated while it picks, at no network cost.

  3. 03

    Badge what you're looking at

    Badges appear on cards as you scroll to them, never all at once, and a Netflix tab sitting in the background is left alone entirely. The badge sits top-right because Netflix uses the top-left corner for its own ribbon and the bottom-left for its own tags.

The difference that matters

There is no server to go down.

Rating extensions normally route every badge, for every user, through a box the developer pays for. That box is the product's whole existence: when it stops, everyone stops at once, and no user can do a single thing about it. This one has nothing to stop.

The usual architecture

Every rating is a request to one host. It can be slow, rate-limited, out of budget, or simply gone — and the extension on your machine has no fallback, because the data was never yours.

The full ratings index lives on your computer, downloaded from IMDb's own published bulk dataset. Nothing is scraped, nothing is proxied, nothing is metered. The one network call left — turning a name into an IMDb id — happens once per title and is then cached forever.

It flags thin evidence

A rating resting on very few votes is drawn with a dashed outline instead of a solid one. An 8.9 from 74 people should not look like an 8.7 from 2.3 million, and in practice the dash catches bad matches too: a famous series showing 90 votes has resolved to the wrong entry, and the dash is the tell.

Questions

The honest answers.

Do I need an API key or an account?

No. There is no sign-up, no key to paste, and no login screen. You install it and it works.

How do I install it?

Clone or download the repository, open chrome://extensions, turn on Developer mode, click Load unpacked and select the folder, then open Netflix. The first run imports IMDb's dataset — about 8 MB, roughly a minute — and badges appear as soon as it finishes.

Where do the ratings actually come from?

From IMDb's own published bulk dataset: 1.7 million rated titles, regenerated daily, downloaded to your machine and refreshed once on each day you use the extension. Ratings are not scraped, and they are not fetched through anyone's server.

What is the one network call you keep mentioning?

The dataset is keyed by IMDb id, but Netflix only gives a display name. Resolving a name to an id uses IMDb's public suggestion endpoint — about a kilobyte of JSON, once per title, cached permanently after that. It is the JSON that powers IMDb's own search box rather than a supported API, so it could change without notice.

Can I change the colours or the cut-offs?

Yes. The defaults are green at 7.5 and above, amber from 6.5 to 7.4, red below 6.5, grey when no rating was found. Those are a taste call, not a fact, so both boundaries drag along a 0–10 scale in the settings and an open Netflix tab recolours as you drag.

What if a badge is on the wrong film?

It can happen. Matching is by name without a year, because Netflix cards don't show one, so remakes and sequels can resolve to the wrong entry — a season 2 title can land on season 1. The tooltip names the matched IMDb title and year precisely so a bad match is visible instead of silent, and Clear matches in the settings forces a fresh resolution.

Why is a card grey?

Because no IMDb rating was found for it. Grey is not a bad score, which is why the dim filter never touches an unrated title — dimming them would bury exactly the new and regional titles worth discovering.

Does it slow Netflix down?

Ratings are read locally, so lookups aren't waiting on a network. Badges are only requested for cards you actually scroll into view, and a Netflix tab sitting in the background is left alone entirely.

Firefox? Safari? Prime Video?

Not yet. It is a Manifest V3 extension, so Chrome today; Firefox would need small changes. The rating pipeline itself is platform-agnostic — only card detection and title extraction are Netflix-shaped — so other streaming services are on the roadmap rather than in the build.

What could break it?

Netflix's HTML is not a contract. Cards are found through Netflix's own test-automation attributes, which are far more stable than class names that change every deploy, but they are free to rename them. If badges ever silently stop appearing, that is almost always why — and because the whole thing is open source, the fix is two functions away rather than out of your hands.
